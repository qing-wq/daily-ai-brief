## 🎙️ 播客精选

### Latent Space — [One Million AI Engineer Special] How Stanford Teaches AI-Native Engineering — Mihail Eric, Monaco
**斯坦福这门爆火的课把结论说得很直白：会用 agent 只是入场券，真正稀缺的是「能设计出可被 agent 验证的系统」的人——而软件工厂的两个瓶颈，一个叫意图，一个叫评审**

- **先说这门课的来历**：CS 146 / 146S《The Modern Software Developer》，Mihail Eric 在斯坦福开的课，今年是第二版（第一版 2025 年秋）。想法始于 2024 年 11 月——那时代码 agent 还很笨，但已经能感觉到开发方式在变，而所有方法论都散落在博客里、没有体系。他花了九到十个月写提案、过课程委员会，才有了这门课。今年之所以重写，是因为自主编码 agent 的能力真的跨了一级：去年那版更像「ISDLC 全景导览」，把每个环节都有哪些 agent 产品巡一遍；今年变成了原则课——上下文工程、以及用设计与架构来消化复杂任务。
- **他对学生说的话比「AI 会不会取代程序员」更刺耳**：每家公司的门槛都变高了。「我第一节课就说：我真心相信每个公司都需要你，但**地板高了很多**」——毕业第一份工作不能只是个大厂 L3，某些方面得接近 senior 才能进门。前提依然是有扎实的计算机基础（算法课是这门课的先修），只是实现细节可以更多地交出去。
- **第一周就让学生写一个 Claude Code**：核心 harness 两百行以内，「不需要超过 106B（斯坦福的入门算法课）的水平」就能跑通一个能对话、能改你文件的编码 agent。然后第二节课更狠：用 MITMProxy 拦截真实 Claude Code 的请求与响应，把 system prompt、计划 prompt、压缩 prompt 全摊开给学生看——从「两百行原理版」到「两天前刚发布的前沿模型真身」，三级跳。
- **一个特别好的「模型 vs harness」案例**：Claude Code 的系统提示词一度长约两万 token，是所有编码 agent 里最长的，后来被砍掉约 80%，再涨、再砍。原因是很多内容（怎么用 git、怎么拆任务）已经被烘进模型权重了。这对任何自己写 agent 的人都有直接含义：**模型弱的时候要给它正反例，模型强了同样的示例就变成过度约束**——难点是知道什么时候该把支架拆掉。
- **他反复强调的一个现实**：绝大多数工程师至今停在「vanilla prompting」，就是「帮我做那个事」。在小项目上够用，但一进几百万行的代码库就不行了。他给的框架叫 Repit（和 Dex Horthy 的 RPI 类似）：**先研究 → 给出几个备选方案让人类拍板 → 再写成 spec / 计划 → 实现 → 用测试收口**。这是能在超大代码库里 scale 的做法。
- **上下文管理最难的地方不是单个 agent，而是 fan-out**：「你永远在经历一个扩张和收缩的过程」——先嫌子 agent 上下文不够，拼命塞；塞完它们又会把你随口一句评论当成法律去执行，做出很蠢的事。所以多 agent 的关键不是并行度，是**每个 agent 拿到多少、拿到什么、什么时候压缩回收**。
- **课程的第二周起是一条很清晰的递进链**：agent 内部机制 → 上下文工程与工具设计（他明确说自己依然 pro MCP，认为它已经是长期标准）→ skill 与流程化 → agent 配置文件（AGENTS.md、CLAUDE.md、hooks、子 agent）→ **agent-ready codebase** → agentic code review → 安全 → 后台 agent → 团队级基础设施（LLM gateway、MCP portal、角色演变）→ 软件工厂。
- **他把「agent-ready codebase」当成后面一切的地基**：大家都迷多 agent、几十个 agent 并行，但真正的第一步是——你的代码库有多可验证、结构有多清楚、agent 能不能读懂。「没有这个地基，多 agent 只是把混乱放大。」他推荐企业先自己跑一份 readiness report。
- **代码评审是今年才浮出水面的真瓶颈**：生成速度上去以后，一天提 30 个 PR 是常态，那然后呢？你亲自逐行 review，你就是整条流水线的限速器，那大规模生成的意义就没了。他给的中间路线是分层的：**在设计好可验证性的前提下，有一类改动可以放心自动批准；剩下的不是逐行看，而是看 spec、看文件级边界**。Monaco 的做法是把 PR 描述写成一份「这次改动到底发生了什么」的 spec，细到文件与接口边界。
- **关于安全的两个观点，值得抄下来**：一是供应链——依赖要 pin 死，「别随手 npm install 就指望链条能跑」；二是**不是所有代码都等价**，数据存储、计费、鉴权这三块「不要写代码」（至少不要放给 agent 自由发挥），其余部分可以放开。Swyx 补了另一半：最安全的代码库是没有依赖的代码库，可那样你只是在用自己的 bug 换别人的 bug——开源的价值是「阳光是最好的消毒剂」，十万人在用，总有人先发现问题。
- **build vs buy 他有一句口诀**：**buy to learn, build to keep**（先买来学，再自己建来守）。Monaco 的实践很具体：code review 试了一圈（CodeRabbit、Graphite、Ellipsis……）第一年全都不够用，一年后再试 Devin，这次是同事自己要求加账号的「有机采纳」；而背景 agent 平台、SRE 工具没有成熟供给，就自建——基于 Coder 做了 Monocoder，Slack 里还有个叫 Hal 的 bot，一半是 AI SRE、一半是客服、一半是 QA（它对着销售和对开发者是两种人格，这件事本身就成了设计问题）。
- **他顺带讲了一个很真实的行业对比**：垂直 AI 公司通常是先从用户侧做起、用前沿模型验证价值，等用户和场景稳了再回头 post-train 自己的模型；模型实验室正好相反，先砸预训练再找用户。他管这叫「agent lab playbook」。成本压力是真的——他直接引了 Harvey 那条「毛利 +50% / -50%」的讨论，说不论数字如何，到某个点你一定会开始想「能不能用开源权重跑得更快」。
- **关于未来的角色，他给了两个瓶颈而不是一个答案**：自动化系统里人来负责的只剩两件事——**意图**（把到底要什么讲清楚）和**评审**（自己动手验证一部分）。而且评审这个瓶颈会先松动，意图会留得更久。「你不再写 prompt，你写的是会写 prompt 的 prompt。」工程师会往「PM engineer」的方向走，往更高层的抽象走，最终可能出现「manager of agents」这种角色——同时他也提醒，Anthropic 的平台工程负责人和产品负责人现在还没合并，「所以别觉得这件事明天就来」。
- **给学生的两条具体建议，比任何宏大叙事都实用**：一是每天花十分钟，用新工具把以前做过的同一件事重做一遍，光这一条就能补掉大部分差距；二是他「第 11 周」的白送内容——**去做 benchmark 和 eval**。写一篇有工程严谨度的评测博客，能把你送进任何一家前沿实验室的门，顺带还能做成生意（SWE-bench 最初就是普林斯顿的本科项目）。
- **最后一段是给「agent 精神病」的清醒剂**：他拿 Steve Yegge 一路升级到多 agent、最后自己承认大部分东西没落地这件事做例子——「如果你不对着真实交付物问责，你就只是在跟 LLM 瞎玩」。作为雇主他说得更狠：他不想招没经历过这一轮、也没从中走出来的人，因为「我现在正在为某人的精神病付工资，很贵，而且我什么都没拿到」。

### Box CEO Aaron Levie (levie on X)
**「每个员工的 token 消耗」这张图还看不到天花板，而且我们现在仍在曲线的早期**

- 他的判断链条很清楚：今年夏秋的模型发布把 SOTA 推进得快到「本来觉得难以维持」的程度，结果是**大多数生产性场景的模型到现在才真正开始可用**——「回想起来，12 个月前的编码基本是垃圾，现在才刚开始变好」。
- 而编码一旦真的跑通，工具调用和电脑操作就跟着来了，于是 agent 才第一次能被扔进金融、生命科学、网络安全这些以前难以自动化的知识工作。「再往下是新的形态：agent 集群和后台 agent，它们吃掉的 token 会远超我们现在能想象的任何量级。」

### Vercel CEO Guillermo Rauch (rauchg on X)
**「以前用户是人，你去做用户访谈；现在用户是 agent，你去跑 eval」**

- 他把这句话当成软件工程流程的根本换轨：旧方式是访谈用户、找灵感、画用户旅程；新方式是**eval 直接喂进工程循环**。他还链接了 Vercel 内部怎么做 eval 的写法。
- 另一条是他给企业的「智能主权路线图」四步：用开放的 SDK 和 harness；用 gateway 把模型选择权留在自己手里；自己掌握 trace 和数据、强制 ZDR；最后用私有推理拥有自己的模型。
- 还有一句宣言式的：新软件时代是「个性化的、完全自有、开源的，而且质量高于它取代的东西」。

### Peter Yang (petergyang on X)
**为什么 Claude 做的设计都长一个样？因为「模型根本不知道自己的偏见是什么」**

- 他把 Anthropic 设计师 Nate Parrott 的方法整理成五条，核心是第三条：在 design.md 之类的文件里**显式警告模型它自己的套路**——衬线字体、米白背景、卡片边缘那几条竖杠。模型没有自我认知，你得替它写出来。
- 其余四条也很好抄：开局就给上下文（截图、喜欢的页面、让它从代码重建真实界面）；难的布局先让它研究同类产品的既有范式；**先做线框图、把核心流程敲定再谈字体和颜色**；最后让它一次给五个方案，你挑喜欢的部分让它 remix 出五个新的。

**GBrain 要换掉 postgres + pgvector：用 Rust 重写后端引擎，把 Vorflux 当软件工厂**
