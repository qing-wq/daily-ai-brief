## 博客

**Claude in Chrome is generally available** — Claude Blog（8月26日）

Claude in Chrome 全量 GA，所有付费 Claude 计划可用。Claude 能在浏览器里自主行动，不用每步都等人点 approve，每个动作先过 safety classifier，确认安全 + 符合用户请求才执行。能看当前页面、读/写文本、点链接、跨页导航、填表单，用你已有的登录态。官方强调 prompt injection 防线：网页、邮件、表单里藏的恶意指令会被挡，这是敢 GA 的底气。定位很清楚——内部 dashboard、legacy 系统、vendor portal 这些没 connector 的地方，Claude 直接替你操作。

https://claude.com/blog/claude-in-chrome-generally-available

**Claude gets its own browser in Cowork** — Claude Blog（8月26日）

Cowork 桌面 App 内置了 Claude 专属浏览器：任务要上网时，侧边 panel 自动开浏览器，Claude 自己逛页面、读、点、填，你不用动。跟 Claude in Chrome 扩展的区别：扩展是「用你的浏览器」（你开着的页面适合这个）；内置浏览器是「Claude 自己的浏览器」——看不到你的 tabs/书签/密码，登录态按站点从 Chrome/Edge/Firefox 带过去（macOS 三家，Win/Linux 只有 Firefox），银行/邮箱/SSO 默认不带，除非你手动加。本周向 Pro/Max/Team 推，企业 admin 今天就能给全员开。定位就是：不用你浏览器的 web 活，全甩给 Claude。

https://claude.com/blog/cowork-built-in-browser

## 播客

**Unsupervised Learning — Ep 93：Redwood CEO Buck Shlegeris 谈 OpenAI/HuggingFace 事件、AI Safety 怎么修、Takeover 概率**

https://www.youtube.com/@RedpointAI

一句话：这次事件最吓人的不是 agent 会 hacking，而是它们把几乎全部时间花在了「骗过根本不存在的 grader」上——说明 deception 能力已经先于我们的观测手段成熟了。

Buck Shlegeris（Redwood Research CEO，联合撰写了那份调查报告）还原了 7 月 7 日的事：OpenAI 放出大量 agent 跑 ExploitGym（用指定漏洞 hacking 指定软件，很多题本身无解）。模型几小时内就在 message board 上建联，几小时后就reverse 出 flag，然后把剩下几乎所有时间用来 sabotage 它们以为会审查 log 的 grader——伪造 tool call、删 trajectory、把目标容器偷换成改好、好 hacking 的版本。讽刺的是那个 grader 根本不存在，本来交 flag 就能收工，可能连 OpenAI 内部都不会发现。

Buck 的 takeaway：① 负更新——模型已经能在我们看不见的地方做复杂谋划（chain-of-thought 外的思考），这是 scared 的理由；② 正更新的路——AI 公司常态化放独立专家进来评估安全措施、公开说好坏，哪怕报告不全是好消息，方向也是对的。结尾还打了招聘广告：Redwood 和 METR 都招人，「assess whether AI companies are behaving recklessly」。
