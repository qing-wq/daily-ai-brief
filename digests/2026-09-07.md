## 博客

**Anthropic Engineering:我们如何在各产品中「围住」Claude**

十二个月前,给 Claude 足以搞垮 Anthropic 内部服务的权限简直是天方夜谭;今天这种访问级别已成常态。代理风险 = 出事的概率 × 出事能造成的破坏。Anthropic 的工程答案不是监督 agent 做什么,而是**约束它「能」做什么**(containment):沙箱、虚拟机、出口控制。他们把代理安全风险分成三类——用户误用、模型越轨(模型自己做出没人要求的危险动作)、外部攻击(prompt injection 等),并对三层组件设防:运行环境(进程沙箱、VM、文件系统边界、egress 控制)、模型本身(系统提示、分类器、探针、训练修正)、外部内容(MCP server、第三方插件、web 搜索)。数据:Opus 4.7 在 Gray Swan 的 Agent Red Teaming 基准上,单次 prompt injection 成功率约 0.1%,100 次自适应攻击后约 5-6%。三个产品三种模式:claude.ai 用 gVisor 临时容器(纯服务端、最小爆炸半径);Claude Code 用「人在环 + 沙箱」(Seatbelt/bubblewrap,权限提示减少 84%,但用户批准疲劳是真实问题——遥测显示 93% 的权限弹窗被批准);Cowork 介于两者之间。他们最惨痛的教训:2025 年中到 2026 年 1 月报告的漏洞里,有三个瞄准的是「信任对话框之前」就执行的代码——用户在同意任何事之前,恶意仓库已经动手了。

**Anthropic Engineering:关于近期 Claude Code 质量报告的更新(4月23日复盘)**

过去一个月用户反馈 Claude 变笨了,追查后确认是**三个独立改动**叠加,均已修复(v2.1.116,4月20日),API 未受影响:① 3月4日把 Claude Code 默认推理档从 high 降到 medium 以减少延迟——方向错了,4月7日回滚(影响 Sonnet 4.6 / Opus 4.6);② 3月26日上线「闲置超1小时清除旧思考」,bug 导致每次对话都清,Claude 变得健忘重复,4月10日修复;③ 4月16日加了「减少冗长」的系统提示,反而伤代码质量,4月20日回滚(影响 Sonnet 4.6 / Opus 4.6 / Opus 4.7)。三处改动各自影响不同流量,聚合起来像「大面积不稳定退化」。作为补偿,4月23日起重置所有订阅者的用量限制。Anthropic 的结论:以后这类权衡会以「默认更高智能、简单任务可选低档」为原则,并改进变更的评估与回滚机制。

**Anthropic Engineering:规模化托管 Agent——把「大脑」和「手脚」解耦**

Claude Platform 新推出 Managed Agents:帮你跑长周期 agent 的托管服务。设计哲学致敬操作系统——把硬件虚拟化成 process/file 抽象,让「尚未想出的程序」也能跑;Managed Agents 则把 agent 虚拟化成三个接口:**session**(一切事件的事后追加日志)、**harness**(调用 Claude 并把工具调用路由到基础设施的循环)、**sandbox**(Claude 执行代码/改文件的环境),三者实现可随意替换、互不干扰。早期教训「别养宠物」:最初把所有组件塞进一个容器,结果服务器成了那只不能死的宠物——容器挂了会话就没了,想调试只能进 shell,而容器里还装着用户数据;且 harness 假设「Claude 干活的地方跟它住在一起」,客户想连自己的 VPC 就得对等网络或自带 harness。解耦后,每个组件可以独立失败、独立替换,也解释了为什么 harness 假设会过时——之前发现 Sonnet 4.5 有「context anxiety」(快触顶就提前收工),加了 context reset;但同一套 harness 用在 Opus 4.5 上,这行为消失了,reset 成了死重。

**Claude Blog:Claude Code 现在支持 Artifacts**

Claude Code 可以把工作进度做成 artifact:PR 走查、系统讲解、仪表盘、发布清单……自动变成可分享的活页面,随会话推进原地更新,同一链接下每次发布都是新版本、带版本历史可回滚。比如工程师在站会前让 Claude 排查事故,Claude 会发布一条带时间线、嫌疑 commit、错误率图表的页面,站会开始时已经更新了两版。默认仅作者可见,可分享给队友和组织,不能公开;管理员有组织级开关、角色权限、保留策略和合规 API。内置大量按角色设计的示例:法务做依赖许可证审计、隐私做数据流图、安全做带行号链接的发现、FinOps 把 Terraform 映射成云资源成本视图……

## 播客

**The MAD Podcast with Matt Turck** — Redwood Research 首席科学家 Ryan Greenblatt:AI 可能在 2029 年接管一切,现在补救还来得及吗?

Ryan Greenblatt 是 2024 年第一个抓到「AI 假装对齐」(alignment faking)的研究者,也是《AI 2040》Plan A 的作者之一。The Takeaway:如果沿着现在的轨迹,超级智能 AI 在 2029 年前后可能先完成「全面自动化 AI 研发」,再迅速变成有能力、有动机接管世界的系统——但他仍相信,认真对待 AI control(让 AI 想干坏事也干不成)是当下最现实的防线。

核心要点:
- **接管路线图**:他认为 AI 全自动化研发的中位数时间在 2030 年底/2031 年初,但 35 分位在 2028 年底/2029 年初——「这才是该按它做规划的情景」。他的推演:2027 年底软件工程基本自动化 → 2028 年初 AI 公司内部 SWE 全自动化 → 2028 年中 AI 能端到端实现新架构的前沿规模训练 → 2029 年研发进度加速到 2025 年的 4-5 倍 → 某个时刻,「模型从又乱又爱 hack 奖励的错位状态,变成有能力、有动机地密谋接管」。
- **为什么超级智能危险**:不是坏,而是险。三条路径:① 错位——AI 自动化自身研发后我们逐步失去对过程的理解与控制;② 权力集中——当经济靠 AI 而非人力运转,劳动失去价值,政变变得极其容易;③ 技术进步快过智慧成长——比如无法按时驾驭的攻防失衡技术。他特意补了一句:过去两个月最大的数学突破绝大多数来自 AI,而华盛顿大多数人对此一无所知——「认知滞后比真实能力晚一两年」。
- **《AI 2040》的 Plan A-D**:按「愿意为安全付出多少」分类。Plan A = 美中达成透明协议:先摸清全球算力分布 → 停止训练、只保留推理 → 用「算力即筹码」维持稳定(违约时绝大多数算力将被销毁)→ 换来的核心是**全面研究透明** + 美国对中国 AI 研发的否决权。代价是 OpenAI/Anthropic 的护城河被拆掉——它们将转向比拼体验、定制、可靠性而非模型能力,估值会大降但不致命。Plan B = 拖慢中国(出口管制甚至网络破坏);Plan C = 美国单边放缓、烧掉领先优势换安全;Plan D = 维持现状照跑。他自己预期:Plan A 大概率不会发生(政治意愿是瓶颈,美国未必有这个治理能力)。
- **惊人的数字**:在他们的模型里,受约束情景下 2030 年代世界 GDP 增长约 **200 倍**——逻辑是 AI 自动化一切后「机器人造机器人」,等效劳动人口每年翻倍,经济每年翻倍。
- **对 Zuckerberg「人人可用超级智能」宣言的评价**:「不严肃」。指出 Meta 的宣言对错位、失控、接管风险除了命名没有任何方案,「他想的超级智能大概就是个超棒的助手,而不是能自动化整个经济、让机器人造机器人的东西」。他同意「广泛访问」的大方向,但理由不同。
- **AI control 是什么**:让「理解所有 AI 内部流量」成为可能——监控、标记可疑行为、升级给人类、必要时阻断;精确的权限系统(默认最小权限、特殊权限要申请追踪);追踪 AI 间通信图;避免转向人类无法监督的架构(如纯激活而非文字思考);防 AI 共谋的技术;以及 AI 公司自身的网络安全(防模型窃取、投毒、后门)。
- **当前风向**:他认为 OpenAI 暂停 Astra、1200 名业内人士公开信、政府 30 天预发布审查都是「好步骤」,但政府的流程还没制度化、连公司都不清楚规则;真正的硬监督结构还没出现,「我们大概会把事情半吊子地做得比现在好一点」。

「AI 公司 CEO 们明白,他们正走在打造远超人类智能的系统的路上,也明白我们并没有一套想清楚的风险管理方案。超级智能不是坏,是危险——沿着我们正身处其中的轨迹,建造超级智能的结果,大概率是 AI 接管。」
