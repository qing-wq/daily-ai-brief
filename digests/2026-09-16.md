## 官方博客

**Anthropic Engineering — How we contain Claude across products**

https://www.anthropic.com/engineering/how-we-contain-claude

一年前 Anthropic 绝不会给 Claude 足以内网搞垮自家服务的权限，今天这已是日常——风险由两部分组成：失败概率（靠 safeguards 和模型训练持续压低）与单次失败的破坏半径 blast radius（随能力和权限只增不减）。Anthropic 的答案是 containment 优先于 human-in-the-loop 监督：遥测显示用户会点掉 93% 的权限弹窗，审批疲劳让监督形同虚设，所以重点是给 agent 的「能力」设边界——sandbox、VM、egress 控制。三种产品三种隔离：claude.ai 用短命 gVisor 容器（server-side、无持久 workspace）；Claude Code 用 OS 级 sandbox（macOS Seatbelt / Linux bubblewrap），权限弹窗减少 84%；Claude Cowork 面向非技术用户，直接上完整本地 VM，credentials 留在 host keychain。血泪教训不少：项目 settings 在 trust 弹窗前就被解析执行、钓鱼 prompt 让模型 25 次里 24 次外传 ~/.aws/credentials、 Cowork 的 egress allowlist 放行 api.anthropic.com 反被借道传文件。核心原则：先做环境层 containment 再做模型层 steering；隔离强度匹配用户的监督能力；少造轮子——出事的全是自研组件，hypervisor、seccomp、gVisor 从没掉过链子。

**Anthropic Engineering — An update on recent Claude Code quality reports**

https://www.anthropic.com/engineering/april-23-postmortem

过去一个月不少用户觉得 Claude 变笨了，Anthropic 查出来是三个独立改动叠加，各自影响不同流量、不同时间，看起来像大面积不稳定退化：3 月 4 日把 Claude Code 默认 reasoning effort 从 high 降到 medium（为缓解 high 模式 UI 假死级延迟），结果是错误 trade-off，4 月 7 日回滚；3 月 26 日上线「闲置超一小时会话清理旧 thinking」降延迟，bug 导致每轮都清，Claude 显得健忘复读，4 月 10 日修复；4 月 16 日加 system prompt 压 verbosity，连带其他 prompt 改动伤了 coding 质量，4 月 20 日回滚。API 和推理层确认未受影响，三个问题都在 v2.1.116 解决。教训是内部用量和 eval 都没第一时间复现用户体感，今后会改流程；作为补偿，所有订阅用户 usage limits 在 4 月 23 日重置。

**Anthropic Engineering — Scaling Managed Agents: Decoupling the brain from the hands**

https://www.anthropic.com/engineering/managed-agents

harness 里全是对「Claude 自己还做不到什么」的假设，而这些假设随模型变强迅速过期（比如 Sonnet 4.5 的 context anxiety 要靠 context reset 治，到 Opus 4.5 这毛病自己消失了，reset 成了死重）。于是 Anthropic 做了 Managed Agents：把 agent 的组件虚拟化成稳定接口——session（append-only 事件日志）、harness（调 Claude 并路由 tool call 的循环）、sandbox（跑代码改文件的执行环境），学操作系统当年用 process、file 抽象屏蔽硬件变迁，接口稳定、实现随便换。反面教材是第一版把三者塞进同一个容器，成了 pets-vs-cattle 里的 pet：容器一挂 session 就丢，只能靠 WebSocket 事件流抢救，分不清是 harness bug 还是丢包。Managed Agents 是 Claude Platform 上的托管服务，专为 long-horizon agents 设计，目标是接口能活过任何一代具体实现。

**Claude Blog — Claude Code now supports artifacts**

https://claude.com/blog/artifacts-in-claude-code

Claude Code 即日起支持 artifacts：把一会话的工作变成自动更新、可分享的实时视觉页面——PR walkthrough、系统讲解、dashboard、release checklist，边干活边自己填。artifact 用整会话的完整 context 构建（代码库、connector、对话本身），不用接数据源搭基建，开口要就行；每次 republish 同链接原地刷新并保留版本历史，header 一键分享。内部最高频用例是 debug：standup 前让 Claude 查 incident，自动出一份带 timeline、可疑 commit 和错误率曲线的页面发团队，开会时已经更新两版了。默认仅作者私有，可分享给 org 内成员，不可公开，管理员有 org 级开关、retention 策略和 compliance API 可见性。

## 播客

**AI & I by Every — How a Professional Writer Writes With AI**

https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL

Every 主持人 Natalia Quintero 对话自家 staff writer Katie Parrott，从她两年前被 crypto 公司裁员、用 ChatGPT 当 career coach 的经历聊起，一路聊到她如今的 Compound Writing 插件。Katie 的核心方法是 context engineering 前置投入：把品牌信息、受众、产品细节等基础 context 一次性喂给模型，后面只管迭代，越到后面跑得越快。她强调人类的「最后一公里」价值——模型知识有 cutoff，独特的研究数据、亲身经历和新鲜 insight 才是让写作不沦为 commoditized 信息的关键，类比是模型是厨房、结构是刀工火候，但食材新鲜度只能人来保证。她还谈了 AI 作为 supportive technology 的一面：bipolar 带来的 inbox anxiety 和拖延，被 Codex automation 和 career coach project 治好，甚至三年没约的家庭医生都是让 agent 找好的。新发布的 Compound Writing 插件 fork 自 Kieran Klaassen 的 Compound Engineering，核心理念 compounding——每次给 AI 的 feedback 都沉淀回系统、下次自动生效，内置 brainstorming、outlining、drafting、substantive edit、line edit 等流程，还把 Vonnegut、Hitchcock、Sorkin、Sedaris 等人的创作框架做成可调用的 reviewer skill，既是写作工具也是写作健身房。她的 AI thesis 是教育与 access 比以往任何时候都重要，否则 AI 的复利只会 compounding 到一小撮早期人群手里。

Takeaway：一开始多花时间搭 context 和流程，后面每个写作任务都是复利；人负责新鲜独特的输入，机器负责跑流程。

原文引用："Two odd years into my AI journey, I have to admit AI hasn't just helped me produce content faster, it has fundamentally changed the scale of what I can do."
